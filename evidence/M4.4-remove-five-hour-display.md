- Architecture mode: `LIMITED_MODE`

This task removes the obsolete five-hour quota row from the browser account panel. Weekly quota,
alias, state, cooldown, last switch reason, and the current-route indicator remain. The change is
limited to display behavior: the browser view model tolerates and ignores a legacy five-hour status
field, while the router and server bridge retain their compatibility boundaries.

No account switch, cross-account continuation, or protocol continuity experiment was performed.

## Test-first evidence

The initial UI contract deliberately supplied one malformed legacy five-hour value and omitted the
field from another account. Four tests passed and two failed because the view model still emitted
`fiveHourLabel` and the built browser bundle still contained the `5-hour quota` label.

After the display implementation changed, the same focused suite passed 6/6. It established that:

- legacy five-hour input is ignored without rejecting an otherwise valid status response;
- the field may be absent;
- account cards expose only the weekly quota label;
- the compiled browser bundle contains neither the obsolete label nor its view-model property;
- manual-switch and all-exhausted behavior remain unchanged.

The local complete matrix passed 235/235 with no skips, and the package syntax check passed.
