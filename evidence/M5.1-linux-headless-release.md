# M5.1 Linux headless release

- Repository: `ChengZhuoCZ/CodexWebManager`

M3.5 remains blocked only on its deferred real-account switching row. M5.1 packages and verifies

evidence.

## Result

M5.1 adds a deterministic, Node-built `ustar+gzip-stored` release for explicit Linux `x64` and
`arm64` targets. The archive contains the account-router source, two POSIX launchers, a private-
prefix-capable installer, a per-file SHA-256 manifest, project documentation, and the license-
boundary notice. It contains no `node_modules` tree, Electron runtime, display-server dependency,
desktop keychain integration, or native package dependency.

The installer accepts an absolute `PREFIX`, requires matching Linux machine architecture and
Node.js 22 or newer, installs into a version-and-architecture-specific `releases/` directory, and
atomically selects it through `current`. M5.1 deliberately does not install systemd units; service
users and supervision remain M5.2 scope.

For the same source, target, and `SOURCE_DATE_EPOCH`, the builder sorts all paths by ASCII code
point, fixes uid/gid/mode/time metadata, writes a USTAR archive directly, and places it in a
runtime-independent stored gzip container. Two independent x64 builds are asserted byte-for-byte
equal before every release test passes.

## Local evidence

The test-first red state was the expected missing `build-linux-release.mjs` import. After
implementation, the focused suite passed 2/2 and validated byte reproducibility, the full manifest,
file digests and modes, the absence of desktop/dependency paths, and rejection of an unsupported
architecture.

The final complete account-router regression passed 161 tests, failed 0, and skipped 7 pre-existing
environment-gated browser rows (168 total). It used mock/fixture data and loopback services only;
no real account configuration was loaded. The first sandboxed full-suite attempt was rejected on
loopback binds, then the same suite passed with permission for temporary `127.0.0.1` listeners.

Local Darwin arm64 can build both target archives but cannot supply Linux runtime acceptance. The
Linux-only verifier correctly failed before extraction with `Linux release verification must run
on a Linux host`. It is intentionally not possible to relabel a macOS run as Linux evidence.

Commands, summarized output, and local artifact digests are recorded in
`evidence/M5.1/local-test-summary.json`.

## Residual risks

- M5.2 must still define systemd units, least-privilege service identities, private configuration
  loading, and independent process restart behavior.
- A GitHub Actions artifact is verification output, not a signed public release. Signing,
  provenance policy, and owner license approval remain release-gate work.
- M0.3, M3.5, and M4.1 real-account switching rows remain unrun and mandatory. M5.1 does not test
  account switching and cannot support a seamless cross-account conversation-continuity claim.
