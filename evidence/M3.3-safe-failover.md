## Acceptance mapping

### Failover only before semantic output

- Only explicit lifecycle/rate metadata is preflight. Text, reasoning, function arguments,
  structural output, terminal events, unknown JSON, non-JSON SSE, and binary WebSocket data are
  semantic by default.
- HTTP/SSE preflight events are held in a bounded gate and discarded when a safe retry occurs.
- WebSocket preflight frames are held until the first semantic event or successful completion.
- Once semantic output is written downstream, the selector is never called again. HTTP/SSE emits a
  fixed in-stream error and WebSocket sends a fixed error followed by a close frame.

### Bounded retry, deadline, and exclusion

- The state machine allows only quota, rate-limit, authentication, network, and upstream-5xx
  failures to retry an initial request.
- Maximum attempts, exponential backoff, `Retry-After`, and total deadline are all bounded.
- The deadline actively aborts selection, the upstream attempt, failure callback, and backoff.
- Each failed account is added to a cumulative immutable exclusion list. A selector that returns an
  excluded account fails closed.
- Selection releases run exactly once, including invalid configurations and transport failures.
- Explicit account failures feed the M2.3 circuit-breaker callback; protocol errors and client
  cancellation do not penalize account health.

### Replay safety and transport behavior

- A replayable HTTP body is buffered within the configured request limit and replayed as identical
  bytes. Chunked overflow receives `413` before account selection.
- Non-SSE responses are buffered within the response limit before downstream commitment.
- Initial WebSocket `response.create` can reconnect only before semantic output. A continuation
  stays on its current upstream connection; replacement returns `unsafe_to_replay`.
- WebSocket handshakes and frames are validated, compression is stripped, message/event sizes are
  bounded, and backpressure propagates in both directions.
- Unclassified `response.failed` events are forwarded as semantic output instead of being guessed
  retryable.

## Residual risks

- Real A-to-B failover remains untested because this device has only one authorized Codex account.
  Mock fixtures are not a substitute for the deferred M0.3, M3.5, and M4.1 account-switch E2E.
- M0.3 already shows that a continuation with `previous_response_id` cannot be assumed portable to
  a replacement connection even for the same observed identity. Cross-account continuation is not
  supported or claimed.
- The standalone CLI does not yet compose the production scheduler, secret provider, circuit
  breaker, and proxy listener. That service wiring remains later DAG work.
- Replay buffers are individually bounded, but high-concurrency memory/FD behavior still requires
  the M6 automated matrix and 24-hour soak test.
- A client control message arriving while a WebSocket response is active is serialized behind that
  response; cancellation/control compatibility needs M3.5 app-server E2E.
- SSE parsing accepts LF and CRLF event separators; malformed or CR-only streams fail closed and
  require compatibility coverage if observed later.
- String credentials supplied by the existing resolver are never logged, but JavaScript strings
  cannot be actively zeroed after a request.
