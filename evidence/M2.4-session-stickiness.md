## Acceptance mapping

### No account switch within an active semantic stream

- `beginSemanticStream()` issues a bounded explicit lease for one routing/account/backend triple.
- While any lease is active, changing the account, changing the backend session, or deleting the
  routing mapping fails closed.
- Ending a lease is idempotence-safe: stale, duplicate, and foreign tokens are rejected.
- A stream may outlive the normal TTL; its active mapping is neither expired nor evicted, and TTL is
  restarted only when the stream ends.
- The M3 integration must acquire this lease immediately before sending the first semantic SSE event.

### TTL and bounded storage

- Inactive mappings expire at the exact configured TTL boundary under a virtual clock.
- Capacity is limited to 1–10,000 entries and semantic leases to 1–16 per routing session.
- After expired entries are pruned, deterministic least-recently-used eviction considers only
  inactive mappings and uses routing-session ID as the final tie-break.
- If every entry is active, new assignment returns an explicit capacity error instead of evicting an
  in-flight route.
- Backend-session IDs have single routing-session ownership while present in the bounded map.

### LIMITED_MODE continuity behavior

- Initial assignment returns `initial_backend_session`/`new_backend_session`.
- Reusing the unchanged account/backend pair returns
  `sticky_backend_session`/`existing_backend_session`.
- At a safe boundary, any account change must use a different backend-session ID and returns
  `limited_mode_new_session`/`new_backend_session` with `cross_account_e2e_verified: false`.
- Assignment accepts only local routing, account, and backend-session identifiers. It rejects
  `previous_response_id`, credential fields, and unknown fields.
- The in-memory mapping is intentionally not restored after router restart. LIMITED_MODE therefore
  requires a visible new backend session (and later bounded rehydration), never forwarding an old
  account's response ID or claiming seamless recovery.

## Residual risks

- Correctness depends on M3 acquiring and releasing semantic leases at the exact SSE boundary,
  including client cancellation and upstream failure paths.
- Persistence is deliberately absent for routing mappings; restart loses stickiness and must visibly
  create a new backend session.
- Bounded transcript rehydration is not implemented here.
- Real cross-account continuity and compatibility remain deferred and unverified.
