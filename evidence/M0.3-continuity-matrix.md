## Observed protocol facts

1. On a persistent Responses WebSocket, Codex sends `previous_response_id` for continuation.
2. Removing that field on the same-account recall call produced a completed response without the
   expected prior-turn fixture, so the captured request did not independently preserve that state.
3. Reopening the upstream WebSocket and forwarding an old `previous_response_id` failed even for
   the same identity in the preserved continuation-reconnect experiment. This is evidence that a
   proxy cannot assume the ID is portable to a replacement connection.
4. A full app-server restart followed by `thread/resume` did recover the fixture. The restarted
   app-server first established fresh upstream state and then issued a continuation call. This
   proves restart/resume behavior, not in-place recovery of an interrupted model computation.
5. An initial request without prior response state could be replayed before semantic output.
6. Once a semantic event was forwarded, the experiment prevented transparent replay.
