## Minimal experiments and findings

1. The unmodified browser bundle loaded its HTML but remained on the startup
   logo when reached through the direct Tailnet HTTP address. The browser error
   was `TypeError: crypto.randomUUID is not a function`; the HTTP IP origin is
   not a secure context.
2. A minimal early-page compatibility shim supplied `getRandomValues` and
   `randomUUID` only when the browser did not expose Web Crypto. After the shim,
   the sign-in/onboarding UI rendered instead of remaining on the startup logo.
3. A raw `codex app-server proxy --sock` bridge did not match the Unix listener's
   WebSocket text framing. The desktop initialization timed out after about
   30 seconds.
4. A bounded, no-payload-logging Node bridge converted stdio JSON lines to Unix
   WebSocket text frames. A sanitized `initialize` probe then succeeded, and
   the deployed desktop handshake completed in 49-50 ms.
5. The upstream instance uses its own App Server, state directory, Unix socket,
   systemd credential mount, Web service, release tree, and port. It does not
   route model traffic through the account-switch router.

The HTTP Web Crypto fallback is not suitable for security-sensitive identifiers.
The preferred follow-up is an HTTPS Tailnet origin, which restores the browser's
native Web Crypto implementation.

## Routed startup optimization

Sanitized startup probes identified two avoidable delays:

1. default catalog calls waited on unused app/plugin/MCP discovery;
2. the pinned desktop bundle was transferred uncompressed at 22,822,120 bytes.

The routed adapter now terminates only default unscoped empty catalog reads
locally. Explicit refreshes, thread-scoped reads, and all non-catalog methods
still reach App Server. The exact content-hashed desktop bundle is precompressed
and served only when the browser explicitly accepts gzip.

```text
app/list:              about 5840 ms -> 1 ms
plugin/list:           about 3967 ms -> 0 ms
mcpServerStatus/list:  about 2256 ms -> 1 ms
main bundle transfer:  22,822,120 bytes -> 5,114,549 bytes
fresh routed navigation after optimization: about 8.7 s
post-restart navigation: about 6.3 s, composer visible on the next bounded poll
```

The existing startup loader remains visible while the large desktop bundle is
parsed, so the page no longer presents an unexplained blank surface.

## Residual risks

- Any Tailnet principal allowed to reach port 8215 can operate the host with the
  `codex` service user's workspace authority and consume the configured account.
- Direct HTTP requires a non-cryptographic browser compatibility fallback.
  Prefer a Tailscale HTTPS hostname before broader use.
- The App Server credential can expire or be revoked and then needs an explicit,
  user-authorized replacement.
- Upstream lists terminal support as incomplete; the extracted macOS `node-pty`
  native binary was not qualified on Linux.
- Statsig telemetry requests were blocked by the browser test environment and
  emitted warnings; the Codex request path still completed.
- Only one usable real account is configured, so the deployed A-to-B switch
  cannot yet be exercised with two real accounts. Synthetic failure injection
  qualifies the switch machinery, not a live two-account E2E.
- Cross-account continuity remains unverified. Switching creates a new backend
  session and must not be described as seamless or as restoring an in-flight
  computation.
- The M6.3 strict CI baseline needs re-qualification after this task is pushed.
