## Test-first findings

The first contract run failed because the security audit runner was absent. After the first
implementation, the repository scan failed closed on three live-shaped synthetic credential
strings in tests. Those fixtures were changed to runtime string composition; no path or line was
broadly allowlisted, so an accidentally committed value with the same shape remains a failure.

The initial systemd inspection also found that all three services had least-privilege isolation but
did not explicitly disable core dumps. Each service now sets `LimitCORE=0` before loading any
credential, and the shared unit contract requires that setting exactly once.

## Audited controls

`packages/account-router/security-audit.json` maps all M6.3 acceptance boundaries to executable
tests. The runner fails closed for invalid policy, unsafe references, forbidden secret filenames,
symlinks, oversized or binary/unparseable files, common credential shapes, a changed protected UI
baseline, failed or skipped focused tests, and missing private evidence paths.

- structured logs redact sensitive keys, email addresses, bearer values, known token shapes, errors,
  circular data, and secret leases;
- admin endpoints require the exact bearer token and return bounded, whitelisted payloads;
- server and browser bridges project only approved status fields and never expose credential
  bindings or authorization values;
- route normalization rejects absolute-form, authority-form, traversal, encoded, fragment, control,
  and unallowlisted targets before upstream resolution;
- request headers cannot select an upstream origin, so the operator-controlled fixed origin is not
  an inbound open proxy or SSRF parameter;
- all Linux services remain loopback or Unix-socket only and now disable core dumps.

## Residual risks and explicit non-claims

- M6.2 remains `rejected`: the user stopped and skipped the required 24-hour soak. M6.3 does not
  replace that release gate.
- The prior real-account protocol and account-switch E2E gates remain deferred. These fixture and
  static security results do not prove cross-account response-chain portability.
- The upstream origin is operator-controlled configuration. Inbound request targets and headers
  cannot choose it, but an administrator with configuration write access can intentionally point
  the router at another HTTP(S) origin.
- The scanner covers tracked and non-ignored untracked repository files and common credential
  shapes; it complements but cannot mathematically prove the absence of every possible secret
  encoding.
