## Initial inspection

The package starts with 186 Node test rows and separate release/systemd workflows. There is no
single checked-in matrix that classifies required suites, proves each required fault is exercised,
fails closed when a required row disappears, or emits one sanitized machine-readable summary.

## Test-first evidence

The first contract run failed with `ERR_MODULE_NOT_FOUND` because neither the matrix manifest nor its
strict runner existed. After implementation, a local E2E-only run without a prepared pinned
codex-web checkout reported 23 total, 16 passed, and 7 skipped. The runner rejected that otherwise
green Node result because release-gate E2E rows may not be skipped.

The first GitHub run,
[`30249408726`](https://github.com/ChengZhuoCZ/CodexWebManager/actions/runs/30249408726),
then produced a useful runtime-compatibility red state: Node 24 passed, while Node 22 cancelled the
pending status-bridge timeout test because the deadline timer had been unreferenced. With no other
referenced event-loop handle, Node 22 could exit while the promised deadline was still pending.
The status bridge now keeps the timer referenced until a response arrives, the stream connects, or
the deadline fires. This is a production correctness fix, not a test-only workaround.

## Auditable matrix

`packages/account-router/test-matrix.json` classifies every checked-in `*.test.mjs` file into
exactly one of three suites. The contract test compares the manifest against the test directory, so
adding an unclassified file, omitting a file, or assigning a file twice fails the build.

- unit: 20 files and 108 tests;
- integration: 12 files and 65 tests;
- E2E: 6 files and 23 tests.

The runner writes only a mode-0600 sanitized summary. It rejects an invalid or incomplete manifest,
unknown arguments, missing absolute summary paths, a failed suite, inconsistent totals, timeouts,
and any skipped release-gate test. It records only platform/version, counts, bounded test names, and
explicit no-real-account/no-switch claims.

The E2E suite uses the exact pinned codex-web revision
`888692f7d885118c6a92bbaf60cf2121f5947adf`. CI runs `npm ci`, checks that tracked and staged
upstream diffs remain empty, executes every formerly gated overlay test, and runs active,
all-exhausted, and bridge-disabled UI smoke scenarios. Every smoke records
`account_switch_scenario_executed:false`.

## Required failure injection

`failure-injection-matrix.test.mjs` exercises each required failure through real loopback HTTP
services and the complete model proxy/failover path:

1. quota response classified as `quota_exhausted`;
2. generic HTTP 429 classified as `rate_limited`, with a long `Retry-After` capped;
3. HTTP 401 classified as `auth_expired`;
4. connection loss before headers classified as `network_error`;
5. HTTP 503 classified as `upstream_5xx`;
6. truncated pre-semantic SSE classified conservatively, discarded, and replayed only on a
   different account fixture.

Each row verifies cumulative account exclusion, one release per selected account, and recovery from
the second fixture. The manifest separately pins both mandatory SSE safety boundaries:

- before semantic output, buffered/truncated bytes may be discarded and a bounded retry may run;
- after a semantic event, the existing proxy test emits `unsafe_to_replay` and never selects the
  second account.

Retry attempt, exponential-backoff, `Retry-After`, and total-deadline bounds remain covered by the
state-machine suite.

## Residual risks

- Automated E2E uses pinned upstream source plus fixture services and UI states; it does not invoke
  a real account or prove account-bound response-chain portability.
- User-deferred M0.3, M3.5, and M4.1 real-account switching rows remain blocked and mandatory for
  any future seamless-continuity claim.
- This matrix runs on Ubuntu x64. Linux arm64 release construction remains covered by M5.1, but the
  complete M6.1 suite did not run on arm64.
- A passing short matrix does not replace the mandatory M6.2 24-hour soak test.
