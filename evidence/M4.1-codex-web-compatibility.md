Support directory. The harness was corrected to give the UI process an isolated private `HOME` and
`XDG_CONFIG_HOME`; it already used an isolated `CODEX_HOME`. The corrected run passed:

- router CLI started both loopback listeners;
- pinned codex-web started against `codex-router-cli.mjs`;
- `GET /` returned `200 text/html` with a valid document;
- no credentials or account identity were persisted;
- account-switch execution remained false.

Machine-readable results are in `evidence/M4.1/codex-web-smoke-summary.jsonl`.
