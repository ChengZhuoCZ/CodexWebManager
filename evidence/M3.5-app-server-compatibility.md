## Outputs

- A runtime composition joins the account catalog, private credential provider, scheduler, circuit
  breaker, failover state machine, model listener, and admin listener.
- The CLI loads only public account metadata from a bounded local JSON file and loads Codex and admin
  credentials from private files. Client authorization, cookies, and account-selection headers are
  not trusted.
- A retryable failure is recorded by the circuit breaker before the selected-account lease is
  released, preserving correct half-open probe semantics.
- A clean-room E2E harness starts the real Codex App Server against the router, uses fixture-only
  prompts with approvals disabled and a read-only sandbox, and writes only redacted summary fields.

## Blocker and residual risk

The acceptance row requiring an approved A-to-B account-switch E2E remains blocked because this
device has only one distinct user-authorized Codex account. That row is not simulated, waived, or
reported as passing. This evidence proves same-account compatibility and historical resume only.

M0.3 previously showed that an old `previous_response_id` failed on a replacement upstream
connection even for the same account. Consequently, successful App Server history rehydration must
not be described as in-place recovery of an upstream computation or seamless cross-account
continuity.
