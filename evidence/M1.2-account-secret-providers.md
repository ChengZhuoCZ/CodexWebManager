## Acceptance mapping

### Public metadata separated from credentials

- Public metadata is frozen and limited to `id`, `alias`, `enabled`, `priority`,
  `max_concurrency`, and model `provider`.
- `secret_provider` and `credential_ref` are stored in a separate frozen internal binding.
- Public catalog serialization tests prove that credential references are absent.
- `contracts/account.schema.json` no longer contains credential binding fields.
- Unknown account fields, including raw authorization/token/email fixture fields, fail closed.

### Pluggable secret backend

- `defineSecretProvider()` defines the provider contract.
- `SecretProviderRegistry` supports named provider registration, explicit acquisition, and
  `withSecret()` lifecycle management.
- `SecretLease` stores a private buffer, redacts string/JSON/inspection forms, and zeroes its buffer
  on disposal.
- Registry errors do not echo credential references or provider exception text.
- Fixture providers prove that the registry is backend-agnostic.

### File permissions and redaction

- File provider requires an absolute root, a service-user-owned non-symlink private directory, and a
  service-user-owned private regular credential file.
- Tests reject `0755` directories, `0644` files, symlinks, traversal-like references, empty files,
  and oversized files.
- `stringifyLogRecord()` redacts credential keys, account email, bearer credentials, known token
  shapes, `SecretLease`, binary values, cycles, deep/wide structures, and unsupported values.
- CLI lifecycle output now passes through the structured redaction serializer.

## Secret-scan boundary

Production sources, schemas, configuration, README, evidence, and task state are scanned for
credential values, private keys, known token shapes, and email addresses. Test files intentionally
contain fixture-only values under the reserved `example.test` domain and obvious `fixture-*`
canaries; tests assert that these canaries never survive public serialization or redacted logs.

## Residual risks

- JavaScript strings passed to a secret consumer cannot be forcibly zeroed; callers must not retain
  or log them.
- Linux systemd `CREDENTIALS_DIRECTORY` wiring and service ownership are verified in M5.2.
- Admin API authorization and public response shaping remain M1.3.
- Real account compatibility and switching remain deferred.
