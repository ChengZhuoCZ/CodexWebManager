## Acceptance mapping

### Only allowlisted routes are forwarded

- `contracts/proxy-routes.json` is synchronized exactly with the frozen runtime registry.
- Standard HTTP compatibility is limited to Responses, Responses compact, and models across the
  documented `/v1`, root, double-`/v1`, and `/codex/v1` prefix variants.
- M0.2-observed backend compatibility is limited to:
  - `GET /backend-api/codex/models` over HTTP;
  - `GET /backend-api/codex/responses` over WebSocket;
  - `POST /backend-api/codex/alpha/search` over HTTP.
- Memory was not observed and remains rejected. Unknown backend families and arbitrary suffixes are
  rejected with `route_not_allowed`.

### Path variants and method/transport coverage

- Every accepted prefix variant has a table-driven test and normalizes to one canonical relative
  upstream target.
- Per-route methods are exact; mismatches return a bounded `405` allow list.
- The backend Responses route requires WebSocket and returns explicit `426 websocket_required` for
  ordinary HTTP.
- HTTP routes reject WebSocket transport rather than silently changing behavior.
- Only model routes accept exactly one bounded plain `client_version` query.

### No open-proxy behavior

- Only origin-form request targets beginning with one slash are accepted.
- Absolute URLs, network/authority forms, `CONNECT`, wildcard targets, dot/encoded traversal,
  backslashes, fragments, control bytes, overlong targets, arbitrary queries, and repeated query
  keys fail closed.
- Normalization returns only `route_id`, method, transport, canonical path, and a relative upstream
  target. It has no origin, host, authority, or caller-controlled upstream destination.
- Errors have fixed messages/codes and do not echo the rejected target.

## Residual risks

- M3.2 must enforce this normalizer before opening any upstream connection and implement bounded
  HTTP/SSE body forwarding, backpressure, and cancellation.
- The current Codex runtime defaults to the observed WebSocket route. Its production forwarding
  path remains required and cannot be replaced by an unverified claim that HTTP/SSE is equivalent.
- Auxiliary endpoint response compatibility remains M3.4.
- Real account behavior remains deferred and unverified.
