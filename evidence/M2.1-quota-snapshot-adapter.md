## Acceptance mapping

### Five-hour and weekly windows

- Every canonical snapshot contains exactly `five_hour` and `weekly` window entries.
- Available entries contain a bounded `remaining_ratio`, optional canonical UTC reset timestamp,
  explicit confidence, and no raw provider payload.
- The observer interface is injected, keeping future provider-specific translation outside the
  canonical scheduler boundary.

### Observation time, confidence, and staleness

- Snapshots retain `attempted_at`, nullable `observed_at`, `age_ms`, the configured stale threshold,
  and `fresh`, `stale`, or `unknown` staleness.
- A virtual clock test verifies the exact transition to stale at the configured threshold without
  mutating the original snapshot.
- Per-window confidence is explicit; aggregate confidence is the conservative minimum across both
  windows, so a partial snapshot is `unknown` overall.
- Excessive future clock skew and non-canonical timestamps fail closed.

### Unavailable data is not guessed

- Missing windows have `remaining_ratio: null`, `confidence: unknown`, and `not_reported`.
- Null sources, observer errors, malformed observations, unknown fields, and ambiguous
  `used_percent` input become unavailable snapshots with two null ratios.
- Unknown data is never converted to either 0 or 1.
- Observer exceptions and invalid raw input are not echoed in output.
- `contracts/quota-snapshot.schema.json` documents the nullable and discriminated output shape.
