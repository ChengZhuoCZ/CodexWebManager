## Implemented boundaries

### Independent supervision

`codex-stack.target` wants all three services, while the services use only `Wants=` and `After=` for
availability and ordering. They deliberately omit `Requires=`, `BindsTo=`, `PartOf=`, and stop/reload
propagation. Restart policy is bounded by start-rate limits, nonzero backoff, and explicit stop
timeouts.

### Local-only transports

- router model: `127.0.0.1:18317`
- router admin: `127.0.0.1:18318`
- codex-web: `127.0.0.1:8214`
- App Server: `/run/codex-app-server/app-server.sock`

The wrapper accepts proxy mode only for the exact pinned codex-web invocation and an absolute,
normalized, bounded `.sock` path below `/run/`. Public WebSocket input, arbitrary options, control
characters, traversal, and non-runtime socket paths fail closed. M4.1 direct mode is unchanged when
the socket variable is absent.

### Credential delivery

The units use `LoadCredential=` and `ImportCredential=`. Public environment values contain only
loopback addresses, ports, executable paths, and `%d` credential paths. No credential value appears
in `ExecStart=` or `Environment=`. `ProtectSystem=strict` and explicit mount namespacing isolate the
per-service credential directories, consistent with the systemd
[credential model](https://systemd.io/CREDENTIALS/).

### Common sandbox

All services use the non-login `codex` identity, `UMask=0077`, empty capability sets,
`NoNewPrivileges=true`, private temporary/device/mount namespaces, strict host filesystem
protection, kernel/control-group/clock protection, SUID/SGID and personality restrictions, native
system-call architecture, and only Unix/IPv4/IPv6 address families. State and runtime directories
are mode `0700`.

`MemoryDenyWriteExecute=` is not enabled because the Node.js runtime uses a JIT. Namespace filters
that could silently break an authorized Codex tool sandbox are not guessed without a real protocol
experiment.
