## Scope and method

M0.2 used a clean-room observer under `spikes/m0-protocol-observer/`. It binds only to `127.0.0.1`, forwards an explicitly configured upstream, and persists protocol shape only:

- sanitized path and query-key names;
- safe header names and the presence—not values—of sensitive headers;
- JSON field paths and value types, never values;
- HTTP status/content type;
- SSE or WebSocket event types, never event/frame payloads.

The observer supports HTTP/SSE and WebSocket upgrade forwarding. For WebSockets it removes compression negotiation, passively parses uncompressed text JSON frames, forwards the original frames unchanged, and ignores binary/non-JSON values.

The experiment followed the current official Codex manual for `openai_base_url` and the App Server JSONL sequence: `initialize`, `initialized`, `model/list`, `thread/start`, and `turn/start`. The exact runtime schema was generated with:

```bash
codex app-server generate-json-schema --out /tmp/codex-web-auto-account-switch-m0.2/app-server-schema
```

Official references used:

- [Codex manual](https://developers.openai.com/codex/codex-manual.md)
- [Codex App Server](https://learn.chatgpt.com/docs/app-server.md)

The real-account capture used fixture-only prompts, ephemeral App Server threads, `approvalPolicy: never`, and `sandbox: read-only`. No local tools or file inspection were requested. Raw App Server payloads and stderr text were not persisted; only notification method/item-type names and a stderr line count were retained.

## Residual risks and M0.3 handoff

1. `previous_response_id` is present in continuation and compact frames. M0.3 must test whether that ID is account-bound; no continuity claim is made here.
2. The observed runtime defaults to WebSocket Responses. A production router based only on HTTP/SSE would be incomplete for Codex 0.144.2 unless WebSocket is explicitly and safely disabled by a supported configuration.
3. Memory behavior is not established because the feature is disabled and no route was observed. Enabling experimental memory could create persistent user/account side effects and was not done in M0.2.
4. Real SSE behavior is unobserved; only fixture SSE parsing is proven.
5. Dynamic/custom JSON field names are hashed, so their exact names are intentionally unavailable.
6. The WebSocket observer inspects only uncompressed JSON text frames up to 16 MiB. Binary, non-JSON, and oversized frames are forwarded without shape evidence.
7. The observer is a spike and is not approved as the production account router. It lacks production retry, backpressure, cancellation, limits, authentication, and hardening.
8. Raw App Server stderr was suppressed to avoid accidental secret/account leakage; only its line count was retained.

M0.3 is required before any architecture decision, failover implementation, UI integration, or statement that account switching preserves the original conversation.
