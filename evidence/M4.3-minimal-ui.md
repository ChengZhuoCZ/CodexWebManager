## Result

M4.3 adds an optional, isolated Shadow DOM account panel to the pinned codex-web overlay. It does
not select or rewrite elements inside the bundled Codex application. The panel is attached only
after the same-origin M4.2 status endpoint returns `enabled:true`; a disabled bridge leaves the DOM
unchanged.

The view model copies only alias, state, five-hour quota, weekly quota, cooldown, last switch
reason, and the current-route marker. Unknown quota is shown as `Unavailable`, not guessed as zero
or full. If every enabled account has `quota_exhausted`, the panel displays `All enabled accounts
are quota exhausted.` explicitly.

Manual switch controls are disabled while `active_streams` is nonzero, for the current route, and
for unavailable account states. The new same-origin POST route accepts only `account_alias` plus
`reason: manual`, keeps the admin bearer server-side, bounds response size and deadline, and copies
only known success/error fields. The router admin API remains the authoritative race-safe guard.
UI copy states that a switch starts a new backend session and that cross-account continuity is not
verified.

## Browser verification

The in-app browser rendered three same-origin fixture scenarios compiled from the actual overlay:

- **active stream**: a 360 px-wide panel displayed two account cards, quota values, unknown weekly
  quota, cooldown, last reason, the active-stream warning, and the continuity limitation. Both
  buttons were disabled.
- **all exhausted**: the explicit all-exhausted warning and zero quota values were visible; both
  buttons were disabled.
- **bridge disabled**: the fixture completed initialization and no account-panel host was attached.

Every browser fixture recorded `switch_request_count: 0` and
`account_switch_scenario_executed: false`. Exact DOM/layout observations are saved in
`evidence/M4.3/browser-ui-summary.json`; loopback request counts are saved in the JSONL summaries.

## Acceptance evidence

1. **Show alias, quota windows, cooldown, last switch reason**: unit-derived view models, a pinned
   Vite bundle, and browser DOM snapshots all contain these exact values for two fixture accounts.
2. **Manual switch disabled during active stream**: the active model marks every control disabled,
   request construction throws for disabled controls, browser inspection found two disabled
   buttons, and the same-origin server test forwards only a fixture request that the admin mock
   rejects with `active_semantic_stream`.
3. **All-exhausted state explicit**: model and browser checks both observe the exact warning and
   disabled controls.

The complete account-router regression passes 166/166. Commands and summarized output are saved in
`evidence/M4.3/test-summary.json`.

## Residual risks

- The fixed-position panel is intentionally isolated from unstable upstream internals, but future
  codex-web layout changes may require visual placement review. The panel is collapsible and
  viewport-bounded to limit overlap.
- No accepted manual switch or real A-to-B operation was executed. Only request construction,
  disabled controls, and a server-side active-stream rejection were tested.
- A later codex-web revision requires review and new source digests for both server main and browser
  shim files.
- M0.3, M3.5, and M4.1 approved account-switch rows remain mandatory. M4.3 is UI evidence only and
  does not support a seamless cross-account continuity claim.
